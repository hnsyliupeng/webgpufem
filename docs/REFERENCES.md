# 参考项目代码核查（尚未集成）

以下是读取上游源码后的记录；引用不表示本项目已移植或实现这些功能。

- [fenris 四面体单元](https://github.com/InteractiveComputerGraphics/fenris/blob/master/src/element/tetrahedron.rs)：Tet4/Tet10/Tet20 的单元连接和几何表示；[网格细分](https://github.com/InteractiveComputerGraphics/fenris/blob/master/src/mesh/refinement.rs)目前明确说明只提供特定单元的**均匀细分**。README 称该库自身不提供线性系统求解器，也没有 GPU 加速计划。MIT / Apache-2.0 双许可，使用代码需遵守对应许可证。
- [ngsolve_webgpu 四面体 WGSL](https://github.com/CERBSim/ngsolve_webgpu/blob/main/ngsolve_webgpu/shaders/eval/tet.wgsl)：基于重心坐标和 Bernstein 多项式评估弯曲四面体几何，主要用于 NGSolve 网格和场的 WebGPU 可视化，不是独立生成贴体网格或动力学求解器。
- [DynELA Explicit.C](https://github.com/pantale/DynELA-v.-4.0/blob/github/Sources/dnlFEM/Explicit.C)：C++ 显式求解器代码，含时间积分与时间步长处理。上游项目依赖原生编译和 Python；现有应用并未集成或移植。
- [WeldFormFEM Remesh.C](https://github.com/luchete80/WeldFormFEM/blob/master/Remesh.C)：引用 ParMmg/MMG 的四面体重网格代码；其 README 将接触与重网格标记为 WIP。原项目使用 C++/CUDA，不能直接作为浏览器 JS 运行。

## 浏览器端候选内核

[@loumalouomega/gmsh-wasm](https://github.com/loumalouomega/GMSH-JS) 将 Gmsh 和 OpenCASCADE 编译为 WASM，支持体网格及 STEP 的读写基础设施，但**目前没有接入本应用，也不自动提供 TPMS 的有效 B-Rep**。浏览器构建需 SharedArrayBuffer 和 COOP/COEP 响应头，与直接打开 file:// 的需求冲突；分发静态链接的二进制需遵守 GPL-2.0-or-later。需要先解决隐式 TPMS 到封闭曲面/体域、模型误差、流形性、多材料接口和许可，再实现并验证四面体网格及其质量。

## WildMeshing Toolkit 2.0 / SimWild
- [SimWild tutorial and API](https://github.com/wildmeshing/wildmeshing-toolkit/blob/main/docs/tutorials/simwild.md) and [project](https://github.com/wildmeshing/wildmeshing-toolkit): simultaneous insertion of several closed input surfaces, winding-number region tags including overlaps, followed by envelope-constrained tet optimization. The envelope bounds movement relative to the *discrete input surfaces*, not the underlying TPMS.
- The optional Python backend uses `wildmeshing==2.0.0`, separately licensed by its upstream project. Analytic shared-interface tests pass; actual App hierarchical presets fail geometry and topology checks, and current preflight prevents expensive execution on obviously aliased surfaces. See README for exact GUI results and remaining limitations.

## TPMeSh — direct implicit meshing
- [TPMeSh](https://github.com/zfergus/TPMeSh), inspected commit `10bd8dec6be9ebbabeecaf6130f23e05819ca8c1`, GPL-3.0: the non-periodic pipeline evaluates the continuous implicit function through a custom pygalmesh/CGAL domain, extracts model-box feature edges using a surface mesh, sets mesh radius based on **physical wall thickness / requested elements through thickness**, uses facet distance `0.1 * resolution`, then optionally invokes perturbation and sliver exudation. The periodic pipeline uses `generate_periodic_mesh`; it is valid only where the complete geometry and boundary conditions are periodic.
- Its `ImplicitShell` uses `(S−t|∇S|/2)(S+t|∇S|/2)` as a first-order approximate constant physical thickness, **not** the App's existing threshold fields. Replacing the App fields with this equation would change the user's design. TPMeSh's `mesh_implicit` handles one implicit solid; it does not automatically generate the App's multi-material shared interfaces or protect their triple junctions. Its cleanup removes all but the largest component and deletes very small tetrahedra: neither operation is safe without verifying whether App geometry or materials were removed.
- [CGAL Mesh_3 labelled domains](https://github.com/CGAL/cgal/blob/v6.0.1/Mesh_3/examples/Mesh_3/mesh_implicit_domains.cpp) directly classify a point into a subdomain and create shared interfaces. This repository's experimental `native/cgal-implicit.cpp` applies that idea to the App's actual material classifier. It does **not yet implement** TPMeSh box feature polylines or App multi-material junction protection, and the mesher can fail to discover thin components without sufficient seed/feature handling. A size criterion is not a proof of two elements across every wall.
- [CGAL periodic labelled implicit example](https://github.com/CGAL/cgal/blob/v6.0.1/Periodic_3_mesh_3/examples/Periodic_3_mesh_3/mesh_implicit_multi_domain.cpp): the periodic triangulation has virtual offsets and can store tetrahedra crossing a unit-cell boundary. The experimental App path now meshes a labelled periodic cell and renders its actual tet section, but **does not** clip and stitch the finite 2×2×2 box. The GUI separately reports per-cell quality and material labels and forbids export.
- The experimental periodic path audits each shared material face by vertex identity and one consistent periodic offset, then samples both sides against the App classifier. This checks the quotient mesh only, not a clipped/stitched finite box or a geometric error bound. Per-stage perturb/exude candidates are independently quality- and volume-gated. Four perturb rounds followed by exude and a separate ODT experiment have caused native crashes on the actual App; the exposed path is limited to two rounds and remains experimental, with subprocess failures discarded.
